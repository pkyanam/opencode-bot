# v0.1.6 qualification

Verified September 21, 2026, against commit
`8dc20a1` and OpenCode CLI 2.0.11.

## Automated and native checks

- 158 Vitest tests and 56 Node tests passed; typecheck and production build passed.
- Release CI built the Linux container, checked its runtime binaries and runner
  health, published the image, and published the verified update bundle.
- An isolated real OpenCode service accepted a mid-turn steering message and
  included its stable message ID in the native transcript. Six deterministic
  local model requests exercised continued execution; no paid provider was used.
- Native skill discovery and binary supporting-file preservation passed locally.
- The real CLI installed a self-authored fixture plugin from a loopback npm
  registry, reported it active, and removed it. This does not establish
  compatibility of arbitrary third-party packages.

## Cloud update

A disposable Cloudflare installation ran the current updater with a deliberately
older version marker. Its Computer initially used the v0.1.2 image. The normal
`/api/updates` path upgraded it to the published v0.1.6 release:

1. Verified the release and saved a durable R2 checkpoint.
2. Uploaded assets and the Worker, preserving bindings and the installation's
   Container application link.
3. Rolled the Computer to the published immutable image digest.
4. Restored the checkpoint, passed health checks, and reported `completed`.

The bot ID, instructions, model selection, conversation ID/title, and exact
contents of a workspace file were preserved. The provider catalog returned seven
models, and the new plugin endpoint returned HTTP 200. In the hosted browser,
Discover listed public repository skills, displayed a preview, and installed
`brand-guidelines` with its supporting license file. Temporary deployment
credentials were removed afterward.

This qualification does not claim the older v0.1.5 updater can repair itself;
see the early-preview upgrade instructions in `docs/getting-started.md`.

## Uninstaller and performance

At the owner's request, the actual `ocbot-personal` installation was uninstalled.
The owned Worker, container application, R2 objects/bucket, and both Durable
Object namespaces were verified absent afterward. Local deployment state and
credentials were retained; the installer can start a fresh installation.

Six concurrent catalog reads now share five native registry calls rather than
thirty. Transcript polling deduplicates in-flight reads while execution reads
remain fresh; idle terminal polling backs off. These are request-count and
behavior checks, not claims about provider inference speed or Cloudflare cold
start latency. An attempted bulk-SQL rewrite measured slower than indexed
per-run reads and was not shipped.

## Remaining boundaries

Native desktop packaging and some additional-node management/streaming features
remain in development. Native skill removal is currently a filesystem action;
Discover does not yet expose its own uninstall button. Cloud container rollouts
can take several minutes even when the web UI loads promptly.
